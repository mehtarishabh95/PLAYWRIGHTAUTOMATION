Basic Selectors

The most basic selectors are class and ID selectors. Class selectors are prefixed with a dot (.), and

ID selectors are prefixed with a hash (#). These are straightforward and commonly used locators."

HTML:

<div class="example-class">This is a class selector</div>

<div id="example-id">This is an ID selector</div>

Playwright:

await page.click('.example-class');

await page.click(#example-id');


Attribute Selectors

Attribute selectors allow you to select elements based on their attributes. You can use square brackets to
target elements with specific attributes. These can be very powerful locators.

HTML:

<input type="text" name="username" />

<input type="password" name="password" />

Playwright:

await page.click('input[name="username"]');

await page.click('input[name^="user"]'); // Starts with 'user'

await page.click('input[name$="name"]'); // Ends with 'name'

await page.click('input[name *= "ser"]'); // Contains 'ser'

Selectors vs Locators

Playwright Selectors are low-level strings used to specify how to find elements, like CSS or XPath.

They require manual handling for waiting and element states.

CSS Selectors: Use standard CSS syntax to select elements (e.g., 'div > span', '.className', #id')

XPath Selectors: Use XPath expressions to navigate the DOM structure (e.g., //div[@class='example']').

Text Selectors: Select elements containing specific text (e.g., 'text="Submit"').

Attribute Selectors: Use specific attributes to identify elements (e.g., '[data-test-id="uniqueld"]').

Selectors vs Locators

Playwright Locators provide a higher-level, more robust way to interact with elements. They encapsulate the logic to find
elements on the page and perform actions on them, offering a more flexible and reliable approach than raw selectors.
Locators can handle elements that appear and disappear, ensuring the desired element is interacted with.

Automatic Waiting : Locators automatically wait for elements to be ready before performing actions, reducing the need for
explicit waits.

Chaining : Locators can be chained to narrow down element selection (e.g., selecting a child element within a specific parent).

Assertions : Locators can be used to assert element states (e.g., visible, hidden, enabled).

const locator = page.locator('button.submit');

What is ARIA

ARIA (Accessible Rich Internet Applications) defines a set of roles

to enhance accessibility for web content. These roles provide

semantic information about elements, which assistive technologies

can use to improve the user experience for people with disabilities.

Basic Usage of 'page.getByRole() 
page.getByRole('button', {name: 'Submit' });
Parameters:
.role: The ARIA role of the element you want to select (e.g., 'button', 'heading', 'link').
.options (optional): An object that can contain additional options to refine the search:
. name: A string or regular expression to match the accessible name of the element.
· level: An integer for heading levels (e.g., getByRole('heading', { level: 1 }) for <h1>).
. checked: A boolean to match the checked state of checkboxes and radio buttons.
. selected: A boolean to match the selected state of options in a dropdown.
. expanded: A boolean to match the expanded state of expandable elements like menus.

When to use Role Locators?

Use cases for interactive elements are best for role locators are better.

Benefits of Using getByRole:
.Accessibility Compliance:
. Using roles ensures that your tests are aligned with accessibility best practices, making
your application more accessible to users with disabilities.
.Resilience to DOM Changes:
. Selecting elements by their roles and accessible names can be more stable than relying
on CSS selectors or XPath, which might change more frequently.
·Readability:
. getByRole makes the intent of the test clearer, as it directly references the purpose of
the element rather than its implementation details.

Several HTML elements come with implicit ARIA roles, meaning they have
default roles assigned by their nature without needing an explicit role
attribute. Here are some common examples:
